# lessons

- when a user asks to “update the design” of an existing recreation, preserve the established layout, pacing, and motion system unless they explicitly ask for a new information architecture. treat new brand assets as a skin and content swap first.
- kawaii does not mean rainbow. for a restrained reference like forma studio, use one neutral background, one accent color, and the existing dark/light contrast before adding any secondary palette.
- "boil the ocean" applies to platform capability and technical depth, not interface density. default every dashboard to one current state, one next action, and one compact proof trail; move architecture, diagnostics, and secondary controls behind drill-downs.
- an explicit hosting target is authoritative. before publishing, distinguish the marketing shell from the stateful product and verify that the requested platform can run the product's actual storage and authentication boundaries.
- when the user names a canonical domain, bind and verify that domain before calling deployment done; autogenerated provider aliases are fallback infrastructure, not the product url.
- when the user asks for one routing surface, a redirect to another host does not count. render the requested product route on the canonical origin and verify it returns its own `200` response with no cross-origin `location` header.
- when the robot is attached to another person's computer, treat that machine as the edge node. package an outbound-only handoff for that host instead of continuing to probe or configure the local mac.
